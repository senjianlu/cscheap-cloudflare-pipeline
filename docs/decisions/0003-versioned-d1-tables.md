# 0003:D1 用「版本化的单表多类型 + 内容寻址正文 + 频道指针」,资源放 R2

- 日期:2026-11-19
- 背景:内容要整版原子地上线并能回滚;读取端在请求时从 D1 / R2 读数据渲染;列表、反向链接、sitemap 都是
  跨类型查询;同一份正文在相邻版本间大多不变。
- 决定:
  - Git 内容用单表多类型加 JSON 列:`entries`(语言无关)与 `entry_locales`(每语言一行),类型专属数据放 JSON 列。
    否掉「按类型分表」(新增类型就要迁移,跨类型查询要 UNION)。
  - 每一行都带 `release_id`;一次发布是 `releases` 里的一行,状态只有 `writing` → `ready`。读取端先取
    `channel_pointers`,其后所有查询显式带 `release_id`。上线与回滚都只改指针这一行。
    否掉「就地更新当前数据」(无法原子切换,也无法回滚)。
  - 正文(页对象的规范 JSON)按内容寻址存 `objects`,不可变、跨版本去重;`entry_locales` 只存摘要。
    `object_sha256` 不设外键,其存在性由就绪条件核对。
  - 二进制资源放 R2 的 `assets/<sha256>/<文件名>`,摘要取**实际上传字节**;版本引用的资源记在 `release_assets`,
    R2 上另存一份版本清单供审计与重建。资源必须先定稿(处理后再取摘要),正文才能引用它。
  - 就绪是一条带条件的更新:行数与 `expected` 相符、引用的正文对象都存在、资源已核对,三项同时满足才置为 `ready`。
  - 指针切换是一条带条件的语句:首次激活用带条件的插入,其后用带条件的更新(比较旧值,且目标不等于当前值)。
    重复激活或重复回滚到当前版本判为幂等成功,不改指针。回滚与切换是同一条语句。
  - 这些规则落成 `contract/release.ts` 里的 SQL 常量,与迁移一起由本仓拥有;读取端不建表。
  - `links` 建为 `WITHOUT ROWID`:全部列都在主键里,二级索引因此覆盖反向查询,查询计划稳定走索引。
  - 同步类实体的表结构归同步方,本仓不建。站内全文检索不在本决策内,契约只保留每页的搜索用结构化文本。
- 影响:发布器必须按 `docs/architecture/publishing.md` 的写序实现,并在远端 D1 上复验本地已验证的语句;
  清理任务必须尊重指针(外键已阻止删除被指针引用的版本),并自行定义 `objects` 与 R2 资源的回收规则;
  表结构的破坏性变更须新增迁移并升主版本。
