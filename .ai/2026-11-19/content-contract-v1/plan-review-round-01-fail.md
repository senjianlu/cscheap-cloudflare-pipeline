# Plan 评审:第 01 轮

## 问题清单
- [major] R-01 D1 模型丢失读取端需要的公共元数据。
  - 详情:定位：plan.md:94-103、138、149-150。信封包含 authors、sources、seo.canonical、seo.ogImage，frontmatter 包含 imageAlt，但 entries、entry_locales 和页对象均无对应存储位置；data 又被限定为类型专属数据。依照当前模型发布后，读取端无法恢复作者、来源和 SEO 信息。请明确输入字段到发布字段的映射及有意舍弃的字段，并增加包含这些字段的存储往返断言。
- [major] R-02 site.json 尚不能完整表达方案依赖的配置与频道策略。
  - 详情:定位：plan.md:46、91-92、102、179-188。workflow.by 要求由 site.json 给定，但配置清单没有对应字段；频道允许使用方命名，却没有说明如何映射“预览／生产”及 stage 准入规则；主稿与译文的判定也未明确如何取得语言上下文。测试表没有 site 配置用例。请补齐这些接口，并覆盖自定义频道、非法 by、默认语言不在语言列表、未注册启用类型及主稿／译文上下文的正反例。
- [major] R-03 受控词表和重定向只有输出表，没有可供内容仓使用的输入契约。
  - 详情:定位：plan.md:55、68、90、94-96、153-154。方案要求作者、分类、标签引用受控词表，修改 slug 须登记重定向，但没有定义词表与重定向声明放在哪里、采用什么结构，也没有对应 schema 或验收。数据库表不能替代内容仓的声明格式。请定义输入载体、键与本地化标签结构、重定向记录结构及其契约测试；引用解析和历史比较的执行仍可留给后续校验任务。
- [major] R-04 AST 的既有兼容性承诺缺少可核验的基线。
  - 详情:定位：plan.md:127-138、182、196。方案承诺沿用生产形状且仅做三处扩展，但仓库及任务 assets 中没有既有 AST 定义或脱敏样本；codeBlock、调色板、toc、structuredData 的既有形状也未给出。TC-04 无法据此确定“调色板下标越界”，新实现自造样本通过更不能证明兼容。请提供固定版本的脱敏基线及兼容用例，或明确改为独立的新契约并调整兼容承诺。
- [major] R-05 发布契约未闭合首次激活和不完整版本的阻断条件。
  - 详情:定位：plan.md:146-162、186；AGENTS.md:38-40。当前写序直接进入 ready，遗漏强制要求的回读核对；“带条件 UPDATE”没有明确旧指针、目标 ready 状态及 source/channel 一致性。空数据库也没有可供 UPDATE 的指针行，TC-08 却要求首次切换影响 1 行。请明确指针初始化及空值语义、ready 的完整性前置条件和切换条件，并在本地迁移用例中覆盖首次激活、未 ready／错误归属目标、旧值冲突及失败后指针不变，无需实现完整发布器。
- [major] R-06 将类型提升必填留在 Zod 自定义校验中，会使机器契约遗漏可表达的结构约束。
  - 详情:定位：plan.md:55、114、172、181、184。每个 Git 类型都有独立 JSON Schema，authors 和 seo.ogImage 的必填完全可以用结构约束表达，不属于无法生成的跨字段规则。按现方案仅放在校验函数中，其他语言或编辑器可能接受 Zod 拒绝的 blog.post。请在类型组合后的 Zod 结构中表达这些必填约束，并增加生成 Schema 对相同正反例的验证，至少覆盖缺 authors、缺 seo、缺 ogImage；漂移检查不能替代语义检查。
- [major] R-07 R2 路径生成与资源白名单没有对应验收用例。
  - 详情:定位：plan.md:51、164-167、179-188。现有路径穿越测试仅涉及链接和图标，不能覆盖 assets 路径中的文件名及 manifest 路径中的 source/releaseId，也没有 MIME 白名单测试。请增加 A 档用例，断言合法输入的准确路径，以及非法摘要、绝对路径、分隔符／路径穿越、非法 source/releaseId 和非白名单 MIME 被拒；同时明确 SVG 清洗前后的摘要与准入责任，防止内容寻址和实际上传字节不一致。
- [major] R-08 文件体积限制的校验接口与边界验收不完整。
  - 详情:定位：plan.md:45、138、188。页对象明确按序列化后大小计量，但 item.json 未明确按原始文件字节还是解析后对象计量，也没有承接原始字节检查的接口。仅对解析后对象运行 Zod 无法发现由大量空白撑大的原始文件。TC-10 也只覆盖超限，没有覆盖恰好等于上限和多字节字符。请明确计量口径、限制入口，并增加上限内、等于上限、超一字节及 UTF-8 样本。
- [major] R-09 核心交付“可被读取端引用的契约库”缺少消费侧验收。
  - 详情:定位：plan.md:26、52、58、75、179-188。当前测试只能证明仓库内部代码可运行，没有验证独立项目能通过包入口取得类型和 Zod schema；也未明确 ESM 导出、类型入口及 git 依赖安装时 TypeScript 产物如何可用。请明确分发入口，并增加离线消费侧冒烟用例，验证独立 TypeScript 项目的类型导入及所承诺的运行时导入；不要求实际发布 npm 包或打 tag。
- [major] R-10 TC-06 的 git diff 检查会漏掉首轮未跟踪和新增的 Schema 文件。
  - 详情:定位：plan.md:184。仓库当前没有已跟踪的 schemas 文件，而 git diff --exit-code schemas/ 不检查未跟踪文件；因此首次生成、漏交新增类型 Schema 等情况都可能得到退出码 0，无法证明无漂移。请比较候选生成物与独立重新生成结果的文件集合和内容，并覆盖缺失、新增及内容变化；验收不应依赖先提交文件。
- [major] R-11 TC-09 的卫生检查边界与合法契约产物及使用方无关要求不一致。
  - 详情:定位：plan.md:187；AGENTS.md:43-44。当前“硬编码域名无命中”没有区分使用方私有域名与模板示例、JSON Schema 元数据及文档来源链接；同时将 site.ts 排除在三语列表检查之外，并不符合“语言列表来自使用方配置”的要求，schema 源文件也不能固定使用方语言。请限定禁止值的判据，明确允许的公共标准和保留示例值，并用应通过／应拒绝样本验证扫描器，避免误报合法产物或放过 site.ts 中的使用方配置。
- [minor] R-12 文档回写清单遗漏 publishing.md 和 usage.md。
  - 详情:定位：plan.md:60；docs/architecture/README.md:9；AGENTS.md:50-52。现有约定要求首个实现任务补齐四篇对外契约文档，方案只列 overview 和 contract。请补入 publishing、usage，描述本次已确定的契约并明确后续尚未实现的能力，不必提前实现发布器。
- [minor] R-13 docs.api 的“生成”没有对应注册表声明的正文模式。
  - 详情:定位：plan.md:109、119。注册表将正文模式列为“必有／可选／无”，类型表却使用“生成”。请统一表述，明确“生成”是正文来源说明还是额外的枚举值，并使 docs.api 模板按同一解释校验。
- [minor] R-14 “频道指针是唯一会被改写的行”与 release 状态迁移矛盾。
  - 详情:定位：plan.md:147、161。方案同时要求更新 releases.status。请将不可变约定限定到正确阶段，例如 ready 后的版本内容不可变，并明确 writing 到 ready 的状态更新例外。
